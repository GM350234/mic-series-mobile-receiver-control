# 可行性报告：在 Windows 上给 DJI 手机版接收器做设置软件

日期：2026-11-09  
设备：DJI Mic Mini 2 手机版套装（1 TX + 1 手机版 RX），接收器固件 `02.03.17.00`  
系统：Windows 10 22H2 x64

## 结论

**可行，而且已经做出来了。** 手机版接收器虽然官方没有 Windows 应用，但它通过 USB 暴露了一个厂商自定义接口（MI_06），走 DJI 的 DUML 协议。给这个接口绑定微软 WinUSB 驱动后，用户态程序就能读取状态、写入增益和声道。本项目在真机上完成了 `+6 → 0 → +6 dB` 和 `单声道 → 立体声 → 单声道` 的往返验证。

现成方案里没有 Windows 版，但有三个关键开源项目把路铺好了：

- **lavdeck**（macOS）已经对同款手机版接收器实现了增益/声道控制，证明协议可用；
- **dji-mic-mini-monitor**（Windows）解决了 WinUSB 绑定和读取，证明 Windows 侧能访问 MI_06；
- **DJI-Mic-Control**（协议文档）给出了完整的命令集与帧格式。

本项目的增量工作是把三者拼起来：Windows 下的写入、手机版接收器的 TLV 状态解析、以及一个可用的图形界面。

## 官方现状

DJI Mic Mini 2 手机版接收器是一只 USB-C 直插手机的小接收器，没有屏幕。官方把设置放在 **DJI Mimo** 手机 App 里：

- 增益只能在连接手机后，在 Mimo 的设备页调节；
- 单声道/立体声、监听音量、自动关机等也在 Mimo 里；
- 固件升级同样要接手机，通过 Mimo 完成。

DJI 的 FAQ 明确写了“手机版接收器如何调节增益：连接手机后打开 DJI Mimo，可在设备页面调节增益参数”。DJI Mimo 只有 iOS/Android 版，官方没有 Windows 桌面版；也没有给手机版接收器提供 PC 端配置工具或公开 SDK。

所以“每次拔下来插手机”不是你的操作问题，是产品设计如此。

关键结论：

1. **协议不是黑盒**。手机版接收器的控制流走 MI_06 的 Bulk OUT `0x06` / IN `0x86`，帧有 CRC8 + CRC16，社区已经能稳定收发。
2. **Windows 的唯一门槛是驱动**。MI_06 没有内置驱动，设备管理器是 Problem 28；绑定 `winusb.sys` 后就能读写。音频 MI_01 不受影响。
3. **写入是安全的**。增益和声道是普通设置命令，不涉及固件升级/重启；lavdeck 也在真机上验证过。

## 其它路线为什么不如原生 Windows App

### 1. 安卓模拟器 + DJI Mimo

BlueStacks 等模拟器能装 DJI Mimo，但**不能把 USB-C 接收器直通给模拟器里的 App**。模拟器的 USB 支持通常只覆盖调试/文件传输，不覆盖厂商自定义接口；即使 App 启动，设备页也看不到接收器。用模拟器的音频输入冒充麦克风，也无法改接收器内部设置。

结论：**不可行**。

### 2. WSL2 + usbipd-win + Linux 工具

`usbipd-win` 可以把 USB 设备整只挂到 WSL2 的 Linux 里，然后在 Linux 里跑社区工具。但：

- 设备会从 Windows 脱离，配置时 Windows 侧不能同时录音；
- 手机版 RX 没有现成的 Linux GUI（lavdeck 是 macOS，KDE 项目主要面向标准 RX）；
- 需要装 WSL、内核、usbipd、编译 Rust，步骤远多于一个 exe。

结论：**技术可行，但不适合日常使用**。

### 3. 买标准版接收器

标准版 RX 有屏幕和按键，可以在机身上改设置，也有 3.5 mm 输出。但它比手机版大，失去了“直插手机”的形态，而且要额外花钱。

结论：**能用钱解决，但不是你想要的**。

### 4. 原生 Windows App（本项目）

- 只给 MI_06 绑 WinUSB，音频/HID 不动；
- Python + tkinter，单文件 exe，无需安装运行时；
- 直接写已验证的增益/声道命令，读状态帧；
- 驱动可一键卸载。

结论：**最贴合需求，已实测通过**。

## 实测结果

| 操作 | 发送 | 结果 |
|---|---|---|
| 读状态 | — | 接收器 `DJI Mic Mini 2` / `02.03.17.00`；增益 +6 dB；单声道；降噪开（档位 1）；自动关机开；USB 已连接；TX1 `DJI Mic Mini` 100%，未充电，降噪开 |
| 增益 +6 → 0 | `5B/01`，TLV `39 00 01 00` | ACK `00`，状态帧变为 0 dB |
| 增益 0 → +6 | `5B/01`，TLV `39 00 01 06` | ACK `00`，状态帧变回 +6 dB |
| 单声道 → 立体声 | `5B/01`，TLV `08 00 01 02` | ACK `00`，状态帧声道位变为 2 |
| 立体声 → 单声道 | `5B/01`，TLV `08 00 01 00` | ACK `00`，状态帧声道位变为 0 |
| 自动关机 开 → 关 → 开 | `5B/01`，TLV `10 00 01 00/01` | ACK `00`，状态帧 bit8 随之变化 |
| 修改后录音 | — | Windows 的 `Wireless Mic Rx` 仍正常 |

## 能改什么、不能改什么

**已实现并验证：**

- 接收器增益 −12…+12 dB（5 档，步进 6）
- 单声道 / 立体声
- 接收器 15 分钟自动关机开/关
- 读取接收器与 TX 的固件、序列号、电量、充电、降噪、自动关机、USB 状态、实时电平

**暂不实现：**

- 发射器低切、LED、语音音色、发射器自动关机：这些命令在标准 RX 上有文档，但在手机版 RX 固件上未逐一验证，贸然发送可能被拒绝或产生意外行为
- 接收器监听音量：Mimo 里可调，但手机版 RX 的对应 TLV 尚未确认
- 固件升级：刻意排除，避免变砖
- 降噪开关/档位：手机版 RX 是侧面 O/L/H 硬件开关，软件不应也不能替代

## 风险与限制

1. **非官方**。协议是逆向所得，DJI 后续固件可能改帧格式或命令 ID，届时需要重新抓包。
2. **驱动是第三方绑定**。安装脚本会创建一个本机自签名证书并信任它，用于给“只重定向到 winusb.sys”的驱动包签名。这是社区常用做法，可用 `uninstall_winusb.bat` 完整撤销；但它确实修改了系统的驱动绑定和证书存储。
3. **保修**。改设置本身不刷固件，但任何非官方工具都存在争议；介意的话不要用。
4. **只支持 Windows 10/11 x64**，只验证了一台设备、一个固件版本。
5. **设置范围有限**。它解决的是“改增益/声道必须拔到手机”的核心痛点，不是 Mimo 的完整替代。

## 交付物

- `MicSeriesControl.exe`：单文件 GUI，双击即用；界面为本地 Web 应用（Edge/Chrome 应用窗口）
- `driver/`：WinUSB 绑定与卸载脚本（管理员运行一次）
- `dji_mic/`：完整源码（DUML、WinUSB、控制器、Web 服务）
- `web/`：新版界面（HTML/CSS/JS、Saira 字体、等高线）
- `tools/mic_cli.py`：命令行，可脚本化改增益/声道/自动关机
- `docs/PROTOCOL.md`：协议笔记
- `tests/`：协议单元测试与真实抓包夹具
