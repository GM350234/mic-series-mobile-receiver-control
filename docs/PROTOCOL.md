# 协议笔记：DJI Mic 系列手机版接收器（MI_06）

> 本文由本项目在真机上抓包、逐字节核对后整理，只记录事实，不包含第三方代码。
> 参考来源见 [`CREDITS.md`](CREDITS.md)。固件 `02.03.17.00` 实测。

## 1. USB 拓扑

接收器是复合设备 `VID_2CA3 & PID_4011`，产品字符串 `Wireless Mic Rx`：

| 接口 | 类 | 说明 |
|---|---|---|
| MI_00 | HID | 媒体键（report 0x06）、电话键（0x07）、厂商 collection |
| MI_01 / MI_03 | UAC 音频 | Windows 录音设备 `Wireless Mic Rx`，48 kHz 双声道 |
| MI_06 | 厂商自定义 `0xFF/0xF0` | **控制/状态流**，Bulk OUT `0x06` / IN `0x86` |

Windows 不给 MI_06 装驱动，设备管理器显示 Problem 28；用 `driver/install_winusb.ps1` 把 `winusb.sys` 绑上去即可。音频与 HID 不受影响。

## 2. DUML 帧

```
偏移  长度  含义
0     1     0x55
1     1     整帧长度（含 CRC16）低 8 位
2     1     (长度高 2 位) | 0x04
3     1     CRC8(bytes[0:3])
4     1     sender   0x02 = 主机/App
5     1     receiver 0x5a = 接收器
6     2     sequence，小端，每条命令递增
8     1     命令类型：0x00 推送，0x40 请求并要求 ACK，bit7 = 响应
9     1     命令集，无线麦克风 = 0x5B
10    1     命令 ID
11..  n-13  负载
n-2   2     CRC16，小端
```

- 帧长 = 13 + 负载长度
- CRC8：反射多项式 `0x8C`（即 `0x31` 反射），初值 `0x77`
- CRC16：反射多项式 `0x8408`，初值 `0x3692`；整帧（含 CRC）残差为 0
- 设备会把 iAP2 的 `ff 55 02 00 ee 10` 混进流里，切帧必须靠 CRC，不能只看 `0x55`

已核对：`55 16 04 fc 02 5a 36 f9 40 5b 01 02 00 00 00 00 08 00 01 02 58 2b`
就是“切立体声、序号 0xf936”的完整帧。

## 3. 设置命令 `0x5B/0x01`

负载（9 字节）：

```
02 | index u32 LE（0 = 接收器） | setting id u16 LE | 01 | value
```

| 设置 | ID | 取值 | 状态 |
|---|---|---|---|
| 声道模式 | `0x0008` | `0` 单声道，`2` 立体声（`1` 被拒绝） | 已验证 |
| 接收器增益 | `0x0039` | 有符号 dB：−12、−6、0、+6、+12 | 已验证 |
| 接收器自动关机 | `0x0010` | `0` 关，`1` 开 | 已验证 |
| 发射器静音 | `0x0009` | 0/1 | 未验证（本项目不发送） |

接收器回 `0x80` 响应，序号相同，负载首字节 `0x00` 表示成功、`0xFF` 表示拒绝。
写入后状态推送通常 0.1–0.5 秒内反映新值，应用会等状态确认再报成功。

> 旧版负载布局（`00 | index u8 | ...`）会让手机版接收器从 USB 掉线再以单声道重连，**不要发送**。

## 4. 能力查询 `0x5B/0x12`

请求负载：`index u32 LE | capability id u16 LE`，`0` = 全部，`5` = 声道，`6` = 增益。

响应：`总长 u16 | (index u32 | 长度 u16 | 条目…)…`，条目 = `id u16 | 长度 u8 | 值`。
手机版接收器的增益范围是 −12…+12 dB、步进 6；声道掩码 `0x07`。

## 5. 状态推送 `0x5B/0x03`

负载以 `03` 开头，随后 `总长 u16 LE`，再往后是记录：

```
type u8 | index u32 LE | length u8 | value[length]
```

`index`：0 = 接收器，1/2 = TX1/TX2。接收器每秒推送多次，另有单独的电平帧和身份帧。

### 5.1 接收器记录（type `0x03`）

`h = u16 LE @ value[0:2]`：

| 位 | 含义 |
|---|---|
| bit 5 | 降噪开 |
| bits 3–4 | 降噪档位（0/1/2） |
| bit 8 | 15 分钟自动关机 |
| bits 9–11 | 声道模式（0 单声道，2 立体声） |
| bits 13–15 | 接收器电量档位 |

- `value[2]`：有符号增益 dB
- `value[0x18]`（记录偏移 `0x1e`）：已连接发射器掩码，bit0=TX1、bit1=TX2
- `value[0x1c]`（记录偏移 `0x22`）：bit3 = 通过 USB 连接

### 5.2 发射器记录（type `0x02`）

`w = u32 LE @ value[0:4]`：

| 位 | 含义 |
|---|---|
| bit 2 | 静音 |
| bits 5–6 | 降噪档位 |
| bit 8 | 降噪开 |
| bit 9 | 正在充电（底座触点真实供电才置 1） |
| bits 10–12 | 电量档位，1 = 满，7 = 即将关机 |

- `value[7]`：有符号增益
- `value[6] >> 4`：信号强度
- 电量只有 3 bit、7 档，百分比是估算：1→100%，2→85%，3→70%，4→55%，5→40%，6→20%，7→5%

### 5.3 身份与电平

| type | 内容 |
|---|---|
| `0x01` | 固件 4 字节（倒序、十进制分量）+ 14 字节 ASCII 序列号 |
| `0x04` | 蓝牙 ID 后缀（ASCII） |
| `0x06` | 产品名（ASCII），例如 `DJI Mic Mini 2`、`DJI Mic Mini` |
| `0x05` | 实时电平，1 字节，安静约 30、大声约 75 |

固件 `00 11 03 02` 解码为 `02.03.17.00`（`0x11` = 17）。

## 6. Windows 访问 MI_06 的坑

1. **必须 `FILE_FLAG_OVERLAPPED` 打开**。同步句柄 `CreateFile` 会成功，但 `WinUsb_Initialize` 一律返回 6（`ERROR_INVALID_HANDLE`），极有误导性。
2. **结构体不要 `_pack_=1`**。`USB_PIPE_INFO`/端点描述符按紧凑对齐会让端点地址读成 0、包长读成 0x86，表现为“没有 IN 管道”。
3. **读超时必须先 `CancelIoEx` 并等它收尾**，再释放 OVERLAPPED/缓冲区/事件；否则内核会往已释放内存写完成通知，进程直接崩。
4. **关闭时先取消 I/O、等在途读写退出用户态，再 `WinUsb_Free`**；否则后台读线程可能在 `WinUsb_GetOverlappedResult` 里访问已释放的接口句柄。
5. 设备会持续推送，不需要先订阅；低频读（200–800 ms）就够用。
